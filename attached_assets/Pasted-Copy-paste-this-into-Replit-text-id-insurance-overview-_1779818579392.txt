Fix the Insurance dashboard property card so changing Primary / Secondary / Investment updates the Policy Type shown on the same card.

Current issue:
Inside Dashboard → Insurance, each property address card has an occupancy/property-use dropdown:
- Primary
- Secondary
- Investment

When I change this dropdown, the Policy Type shown on the same property card does not update.

Expected behavior:
When the user changes the occupancy dropdown on the Insurance property card overview:

Primary:
- If property type is Single Family / non-condo / non-townhouse → Policy Type = HO3
- If property type is Condo/Townhouse → Policy Type = HO6

Secondary:
- If property type is Single Family / non-condo / non-townhouse → Policy Type = HO3
- If property type is Condo/Townhouse → Policy Type = HO6

Investment:
- If property type is Single Family / non-condo / non-townhouse → Policy Type = DP3
- If property type is Condo/Townhouse → Policy Type = HO6

Core fix:
The Insurance overview card occupancy dropdown must recalculate the Policy Type immediately and update the same card UI.

Required behavior:
1. User changes occupancy dropdown on Insurance overview card.
2. Card immediately updates occupancy value.
3. If `policy_type_source !== "manual"`, recalculate policy type using:

`getDefaultInsurancePolicyType({ occupancyType, propertyUse, propertyType })`

4. Update the Policy Type display on the same overview card immediately.
5. Save both occupancy and policy type to `insurance_scenarios`.
6. Detailed view for that property should show the same updated values.
7. Values must persist after refresh/logout/login.

Save to `insurance_scenarios`:
- `occupancy_type`
- `occupancy_type_source = "manual"`
- `policy_type`, if recalculated
- `policy_type_source = "default_rule"`, if recalculated
- `user_answer_sources.occupancy_type = "manual"`
- `updated_at`

Manual override protection:
If `policy_type_source = "manual"`:
- Do not recalculate or overwrite `policy_type`
- Still save the changed occupancy
- Keep the manually selected policy type visible

If `policy_type_source` is blank, null, default, or default_rule:
- Recalculate policy type from occupancy + property type
- Save and display the recalculated value

Important:
Do not only update the detailed view.
Do not only update Supabase.
The Policy Type text/value on the Insurance overview card must change immediately after the dropdown changes.

Likely bug:
The overview card’s policy type display is probably reading from a stale `ins.policyType` value or fallback display value and is not being recomputed after the occupancy dropdown state changes.

Fix options:
- Update the local Insurance scenarios state after the dropdown change with the recalculated `policyType`
- Or make the card display derive from the current card occupancy + property type when policy type is not manual
- Prefer updating the saved scenario state so overview and detail stay consistent

Do not create duplicates:
- Update the existing insurance row by scenario id
- If id is missing, use `user_id + normalized_property_key`
- Do not insert a new row

Property type source:
Use the property type already associated with the Insurance scenario/card.
If missing, use the same fallback currently used by the detailed view or dashboard backfill.

Policy type helper:
Use the existing helper:
`getDefaultInsurancePolicyType`

Do not create a second separate policy-type formula.
