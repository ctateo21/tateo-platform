I want to change the Zillow scraper flow inside the Purchase Flow → Property Estimate section.

Current behavior:
- A client enters/selects a home address.
- The scenario is created with automatically populated default/estimated data.
- To get Zillow data, I currently have to manually click a button that says “Pull from Zillow.”
- I do not want the user to have to click that button.

New expected behavior:
When a client enters/selects a home address in the Purchase Flow → Property Estimate section, the Zillow scraper should automatically run in the background.

Flow should work like this:
1. User enters/selects a home address from Google Maps autocomplete.
2. The property/scenario is created immediately using the app’s normal default/estimated values.
3. The user can continue using the scenario right away.
4. In the background, automatically start the Zillow scraper for that selected address.
5. While the Zillow scraper is running, keep the initial auto-populated/default data in the scenario.
6. Once the Zillow scraper finishes successfully, replace only the relevant data points with the Zillow scrape data.
7. Do not require the user to click “Pull from Zillow.”
8. The Zillow scrape should run automatically every time a new property/scenario address is added.

Important:
The Zillow scraper should not block the user from moving forward. The initial/default values should stay visible until Zillow data is returned.

Data replacement rules:
- Replace purchase price with Zillow listing price or Zestimate/home value only.
- Do not use rent Zestimate as purchase price.
- Replace rent estimate only with Zillow rent Zestimate/rental estimate.
- Replace property tax estimate only if Zillow returns a valid tax value.
- Replace insurance estimate only if Zillow returns a valid insurance value.
- Replace beds, baths, square footage, year built, lot size, and property type only if Zillow returns valid values.
- Do not overwrite valid existing scenario data with null, empty, zero, or obviously bad scraped values.
- Do not overwrite user-edited fields if the user manually changes a field while the Zillow scrape is still running.

Please add source tracking for each auto-populated field:
Each field should know whether its value came from:
- app default estimate
- Google address data
- Zillow scrape
- user manual edit

This matters because:
- Zillow can replace app default values.
- Zillow should not replace values that the user manually edited after the scenario was created.
