1. **A saved value column** for every user-editable field.
2. **A source column or `user_answer_sources` JSON field** so Zillow/default/API data does not overwrite manual user edits.

My read based on everything you have already added: **you probably do not need one giant new table**, but you may still need **missing columns or missing mapper fields** in each service table. The most likely issue is not just SQL — it is usually one of these:

1. the column exists, but the frontend does not send it to Supabase
2. Supabase saves it, but the loader does not map it back into state
3. overview cards use old calculated state instead of saved scenario state
4. Zillow/default effects overwrite the saved manual value
5. source tracking is missing or not respected
