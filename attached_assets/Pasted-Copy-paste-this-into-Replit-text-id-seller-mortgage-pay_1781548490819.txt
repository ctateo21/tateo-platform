```text id="seller-mortgage-payoff-refi-amortization-statement"
Update Sell Your Home mortgage payoff logic so it can pull or estimate the mortgage balance from three sources.

Current issue:
On the Sell Your Home tab, Mortgage Payoff is currently user-entered/defaulted, but it should be smarter.

Goal:
For each Sell Your Home property, determine Mortgage Payoff using this priority:

1. If the same property address exists in the Refinance tab, bring over the current mortgage balance from that Refinance scenario.
2. If no matching Refinance scenario exists, estimate the mortgage balance using an amortization calculation from the property’s last sold date to today.
3. Allow the user to upload a current mortgage statement and extract the current mortgage balance, the same way the Refinance tab already does.

Scope:
Dashboard → Sell Your Home
- overview cards/rows
- detailed home view
- Sale & Costs tab
- Net Proceeds Breakdown
- Estimated Net Proceeds calculation
- Mortgage Payoff input/autosave

Mortgage Payoff source priority:
Use this order:

1. Manual user-entered Mortgage Payoff
2. Mortgage statement uploaded by user
3. Matching Refinance scenario mortgage balance
4. Amortized estimate from Zillow/property cache last sold data
5. Existing seller_scenarios.mortgage_payoff value
6. Fallback to $0 if nothing is available

Manual override protection:
If user manually edits Mortgage Payoff in Sell Your Home:
- set `mortgage_payoff_source = "manual"`
- do not overwrite it with Refinance, amortization, Zillow, or statement parsing
- preserve after refresh/logout/login

If user uploads a mortgage statement:
- set `mortgage_payoff_source = "statement"`
- save the extracted balance
- do not overwrite it with Refinance or amortization unless user chooses reset/recalculate

PART 1 — Pull mortgage balance from Refinance tab if same property exists

When a Sell Your Home scenario loads, check whether the same property exists in Refinance/tracked loans.

Match by:
1. normalized_property_key
2. exact normalized address fallback
3. full_address fallback only if normalized key is missing

Look in the Refinance/tracked loans data for fields like:
- current_mortgage_balance
- mortgage_balance
- unpaid_principal_balance
- current_loan_balance
- loan_balance
- principal_balance
- payoff_balance

Use whichever field the Refinance tab currently uses for mortgage balance.

If a match exists:
- copy that mortgage balance into Sell Your Home Mortgage Payoff
- save it to `seller_scenarios.mortgage_payoff`
- set `mortgage_payoff_source = "refinance"`
- update `updated_at`
- recalculate Net Proceeds immediately

Do not create duplicate seller scenarios.
Do not create duplicate refinance scenarios.
Do not overwrite if `mortgage_payoff_source = "manual"` or `"statement"`.

Display:
If the value came from Refinance, show a small muted note near Mortgage Payoff:
“Pulled from Refinance scenario”

PART 2 — If no Refinance match exists, estimate payoff using amortization

If no Refinance scenario exists for the same address, estimate the current mortgage balance using Zillow/property cache data.

Required inputs:
- prior purchase price / last sold price
- last sold date / purchase date
- current date
- assumed initial loan amount

User request:
Assume the purchase price as the initial loan amount value on the purchase date.

So:
initialLoanAmount = lastSoldPrice

Use Zillow/property cache fields such as:
- last_sold_price
- last_sale_price
- prior_purchase_price
- previous_purchase_price
- lastSoldPrice
- priceHistory sale amount
- last_sold_date
- last_sale_date
- prior_purchase_date
- previous_purchase_date
- lastSoldDate
- priceHistory sale date

Important:
Do not use Zestimate or current list price as prior purchase price.
Do not use current estimated sale price as initial loan amount.

If multiple price history entries exist:
- use the most recent prior sale event
- extract sale date and sale price
- ignore listing events, price changes, tax assessments, and Zestimate values

Amortization assumptions:
Because we do not know the original loan terms, use these defaults for now:
- Loan amount = last sold price
- Term = 30 years
- Interest rate = 6.50% annual fixed rate
- Start date = last sold date
- Current date = today
- Payments made monthly
- Assume no extra principal payments
- Assume no refinances
- Assume no escrow in balance
- Estimated balance cannot be below $0

Create a shared helper:

`estimateMortgageBalanceFromSale({
  originalLoanAmount,
  annualInterestRate,
  termYears,
  loanStartDate,
  asOfDate
})`

Formula:
- monthlyRate = annualInterestRate / 12
- totalPayments = termYears * 12
- paymentsMade = number of full months between loanStartDate and today
- monthlyPayment = P * [r(1+r)^n] / [(1+r)^n - 1]
- remainingBalance = P * [((1+r)^n - (1+r)^p) / ((1+r)^n - 1)]

Where:
- P = originalLoanAmount
- r = monthlyRate
- n = totalPayments
- p = paymentsMade

If monthlyRate is 0:
- remainingBalance = originalLoanAmount * (1 - paymentsMade / totalPayments)

Clamp:
- paymentsMade cannot be less than 0
- paymentsMade cannot exceed totalPayments
- remainingBalance cannot be less than 0

Save:
- `seller_scenarios.mortgage_payoff = estimated remaining balance`
- `mortgage_payoff_source = "amortized_estimate"`
- optional:
  - `mortgage_payoff_estimate_inputs` jsonb with:
    - originalLoanAmount
    - annualInterestRate
    - termYears
    - loanStartDate
    - asOfDate
    - paymentsMade
    - monthlyPayment
    - sourceSalePrice
    - sourceSaleDate

Display:
If the value came from amortization, show a small muted note:
“Estimated from last sale history”

Also show a small disclaimer:
“Estimated payoff only. Actual payoff may differ based on refinances, extra payments, fees, escrow, and lender payoff quote.”

PART 8 — Data source resolver

Create or update a shared resolver:

`resolveSellerMortgagePayoff({
  sellerScenario,
  trackedLoans,
  propertyCache,
  normalizedPropertyKey,
  address,
  today
})`

Responsibilities:
1. If seller mortgage payoff source is manual, return manual value.
2. If source is statement, return statement value.
3. Search Refinance/tracked loans by normalized property key/address.
4. If Refinance match exists, return Refinance mortgage balance.
5. If no Refinance match exists, resolve last sold price/date from Zillow/property cache.
6. If sale price/date exist, run amortization estimate.
7. Return value, source, and metadata.
8. Never create duplicate scenarios.
9. Never overwrite manual or statement values.
```
