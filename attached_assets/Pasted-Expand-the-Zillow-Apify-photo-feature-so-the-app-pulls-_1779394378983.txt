Expand the Zillow/Apify photo feature so the app pulls, stores, and displays all available listing photos, not just the primary dashboard image.

Current behavior:
The Zillow/Apify integration now successfully loads one photo for the dashboard view of a property. That part is working correctly.

New goal:
When Zillow property data is scraped through Apify, collect all available property/listing photos from the Zillow response and allow the user to view them inside the full property detail/estimate view.

Start with photo URLs only. Do not download or store image files yet.

Reason:
- Faster
- Cheaper
- Less storage
- Easier MVP
- Lower copyright/storage risk
- Still lets the dashboard and property detail pages look better

Step 1 — Inspect the current Apify Zillow response

Inspect the full raw Apify/Zillow dataset response and look for any photo/image fields, including:

- photos
- images
- imageUrls
- photoUrls
- imgSrc
- hiResImageLink
- responsivePhotos
- media
- carouselPhotos
- image
- propertyImages
- listingPhotos

Normalize all valid photo URLs into this structure:

propertyPhotos: [
  {
    url: "",
    caption: null,
    width: null,
    height: null,
    source: "Zillow via Apify"
  }
]

Set:

primaryPhotoUrl = propertyPhotos[0]?.url || null

If no photos are found:
- propertyPhotos = []
- primaryPhotoUrl = null

Step 2 — Add or reuse photo fields on the property/scenario model

Add or reuse these fields on the property/scenario record:

{
  primaryPhotoUrl: null,
  propertyPhotos: []
}

Apply this to any relevant saved property/scenario model used by:
- Purchase property estimates
- Refinance properties
- Insurance properties
- Shared property cache, if applicable

Step 3 — Save photos with Zillow/property cache data

When a Zillow scrape succeeds:
1. Normalize the Zillow data.
2. Extract all available property photo URLs.
3. Remove duplicate URLs.
4. Skip invalid or empty URLs.
5. Save primaryPhotoUrl.
6. Save propertyPhotos.
7. Store these fields with the property scenario and/or property cache record.

If cached Zillow/property data is used instead of a fresh scrape:
- Load primaryPhotoUrl.
- Load the full propertyPhotos array.
- Display them the same way as fresh scrape results.
- Do not re-scrape just to display photos if cached photos already exist.

Important:
- Do not expose the Apify token to the frontend.
- Do not download image files yet.
- Store only image URLs.
- Do not store duplicate photo URLs.
- If the same URL appears multiple times, keep only one.
- If the image URL is invalid or empty, skip it.
- Do not let missing photos break the Zillow scrape flow.

Step 4 — Dashboard display

The dashboard property card should continue showing the primary photo.

Use primaryPhotoUrl on:
- Dashboard → Purchase property rows/cards
- Dashboard → Refinance property rows/cards
- Dashboard → Insurance property rows/cards, if applicable

Fallback behavior:
If no primaryPhotoUrl exists:
- Show the existing placeholder image/icon.
- Do not leave a broken image.
- Do not show empty white space.

Step 5 — Property detail / full estimate photo carousel

When the user clicks into a property card and opens the full property estimate/details view, show a photo carousel.

Placement:
Inside the property detail/full estimate view, place the photo viewer above:

“Review Your Answers”

This is the area that reviews the user’s answers from Pages 1–3.

Start with the Purchase property estimate detail view first if that is the smallest safe change. If the same component/data already supports Refinance and Insurance detail views, reuse it there too.

Carousel behavior:
1. Show one photo at a time.
2. Add a right arrow to move to the next photo.
3. Add a left arrow to move to the previous photo.
4. Add photo count if simple:
   Example: 1 / 24
5. If only one photo exists, hide or disable arrows.
6. If multiple photos exist:
   - Right arrow moves to the next photo.
   - Left arrow moves to the previous photo.
   - At the last photo, either loop back to the first or disable the next arrow.
   - At the first photo, either loop to the last or disable the back arrow.
   - Use whichever behavior is simpler and cleaner, but keep it consistent.
7. If possible, allow keyboard navigation with left/right arrows.
8. The carousel should not reset to photo 1 every time a user edits an answer unless the active property changes.
9. The carousel should be tied to the active property/scenario ID.

Make the carousel feel similar to Zillow’s listing photo workflow:
- Large clean image area
- One photo at a time
- Simple left/right arrows
- Clear progress/count
- Smooth, simple navigation

Image display requirements:
- Keep the image aspect ratio clean.
- Do not stretch or distort photos.
- Use object-fit/contain or cover as appropriate for the existing UI.
- Make it responsive on mobile.
- Do not show a broken image icon.
- If propertyPhotos is empty but primaryPhotoUrl exists, display primaryPhotoUrl as the only image.
- If neither exists, show the current placeholder or a simple property image placeholder.

Step 6 — Reusable component suggestion

Create a reusable component if appropriate:

PropertyPhotoCarousel

Props:
- photos
- primaryPhotoUrl
- propertyAddress
- propertyId or scenarioId

Use it wherever full property details are shown.
