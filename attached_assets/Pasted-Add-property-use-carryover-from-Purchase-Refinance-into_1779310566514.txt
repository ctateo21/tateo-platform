Add property-use carryover from Purchase/Refinance into Insurance when addresses match.

Current issue:
If a user already entered the property use/occupancy type for an address in the Purchase or Refinance tab, the Insurance tab still asks them to enter it again.

Expected behavior:
When an Insurance record/property address matches an address already saved in Purchase or Refinance, the Insurance tab should automatically use the same property use/occupancy type.

Property use values:
- Primary residence
- Second home / secondary residence
- Investment property

Example:
- Purchase tab has: 3102 W Nassau St — Primary Residence
- Insurance tab has: 3102 W Nassau St
- Insurance should automatically show/use Primary Residence.
- The user should not have to enter it again.

Another example:
- Refinance tab has: 123 Main St — Investment Property
- Insurance tab has: 123 Main St
- Insurance should automatically show/use Investment Property.

Matching logic:
Address matching should use a normalized property key, not the raw address string.

Match by:
- street number
- normalized street name
- unit number, if applicable
- ZIP5
- state

Do not rely on city as the main matching field because Google Maps, Zillow, and mailing addresses may use different city names for the same property.

Suggested normalized key format:
`3102-w-nassau-st-33607-fl`

Implementation requirements:
1. When an Insurance property/address is added or loaded, generate its normalized property key.
2. Compare that key against saved Purchase and Refinance records for the same logged-in user.
3. If a matching Purchase or Refinance record exists and has a property use/occupancy value, copy that value into the Insurance record by default.
4. Save the copied occupancy value to the Insurance record.
5. Display the copied value in the Insurance tab/UI.
6. Do not ask the user to re-enter property use if it was successfully matched.
7. If no match exists, then ask/show the property-use field in Insurance as normal.
8. If the user manually changes the property use inside Insurance, preserve that manual override.
9. Once manually overridden, do not keep replacing it from Purchase/Refinance.

Source tracking:
Add or reuse fields like:
- `normalizedPropertyKey`
- `occupancyType`
- `occupancySource`: `"purchase" | "refinance" | "insurance_manual" | "unknown"`
- `linkedPurchaseScenarioId`
- `linkedRefinanceScenarioId`

Priority rules:
1. If Insurance has a manual occupancy override, use that.
2. Else, if a matching Purchase record has occupancy type, use Purchase.
3. Else, if a matching Refinance record has occupancy type, use Refinance.
4. Else, leave unknown and allow the user to choose.

If both Purchase and Refinance match but disagree:
- Prefer the Insurance manual value if it exists.
- If no manual value exists, prefer the most recently updated Purchase/Refinance record.
- If still unclear, show the value but allow the user to change it.
- Do not silently overwrite a manual Insurance selection.

Important:
- This should only carry over the property use/occupancy type.
- Do not merge or overwrite full Purchase, Refinance, or Insurance records.
- Do not show Refinance records as Insurance records.
- Do not change the Insurance tab layout/view.
- Do not touch Purchase persistence in this change unless needed only to read the property-use field.
- Do not use array indexes for matching.
- Use stable scenario/property IDs and normalized property keys.

Auto-save:
- If Insurance occupancy is auto-filled from Purchase/Refinance, save that to the Insurance record.
- If the user changes the Insurance occupancy manually, auto-save the manual override.

Acceptance test:
1. Add a Purchase property with occupancy type Primary Residence.
2. Add an Insurance property with the same address.
3. Confirm Insurance automatically shows Primary Residence.
4. Confirm Insurance does not ask the user to enter property use again.
5. Add a Refinance property with occupancy type Investment Property.
6. Add an Insurance property with that same address.
7. Confirm Insurance automatically shows Investment Property.
8. Manually change the Insurance property use.
9. Confirm the manual Insurance value saves.
10. Refresh/logout/login.
11. Confirm the manual Insurance value is preserved and not overwritten.
12. Add an Insurance property with no matching Purchase/Refinance address.
13. Confirm Insurance asks/allows the user to choose property use normally.
14. Confirm Insurance tab layout/view does not change.
15. Confirm Purchase and Refinance records are not modified by this Insurance change.

- Which normalized address key function is used or added

- Which Insurance occupancy fields are updated
- How manual Insurance overrides are preserved
- Which files/functions were changed
