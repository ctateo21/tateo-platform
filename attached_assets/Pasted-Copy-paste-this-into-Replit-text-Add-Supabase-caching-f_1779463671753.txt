Add Supabase caching for the Realtor.com scraper, the same way Zillow/Apify data is cached.

Current issue:
The Realtor.com scraper is being used for Market Analysis comps, but it should not scrape Realtor.com every time a user opens a For Sale property or every time Market Analysis runs.

Goal:
When Realtor.com scraper `memo23/realtor-search-cheerio` runs, store the normalized results in Supabase so future market analyses can reuse the saved Realtor.com data instead of scraping again.

This should work similarly to the existing Zillow/Apify property cache.

Expected behavior:
1. Before running the Realtor.com scraper, check Supabase for cached Realtor.com market data.

4. Normalize the scraper results.
5. Save the normalized results to Supabase.
6. Use the saved/normalized Realtor.com data in Market Analysis.
7. Do not scrape Realtor.com again until the cache is stale.

Cache freshness:
Use the same Friday 8:00 AM Eastern weekly cycle as Market Analysis.

Rules:
- Realtor.com data should refresh once per week per property/market.
- The weekly cache cycle starts Friday at 8:00 AM Eastern.
- If cached data exists for the current Friday cycle, use it.
- If cached data is missing or stale, run the scraper once.
- Save new results to Supabase.
